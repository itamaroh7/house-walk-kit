# קריאת שרטוט של תכנית קומה

[English](reading-a-drawing.md)

איך הופכים שרטוט של אדריכל (צילום, סריקה או PDF של תכנית קומה) לקובץ תכנית שתואם לו, קיר אחרי
קיר. קריאה בעין נותנת בית שבערך נכון ושגוי בכל פרט: קנה מידה ממספר אחד שנקרא לא נכון, קירות
פנימיים מנוחשים, קו מידה שנחשב לקיר. כל שלב כאן מחליף ניחוש במדידה.

שני הכלים כותבים לתיקייה `drawing-work/` בפרויקט, ש־git מתעלם ממנה: השרטוט והחיתוכים שלו נשארים
במחשב שלכם.

## 1. קנה המידה בא משרשראות המידות של השרטוט עצמו

בשרטוט אדריכלי יש שרשראות מידות: קווים דקים עם סימני קצה מול פני הקירות ומספר לכל קטע, בס"מ.
משתמשים בהן, ולא במידה שמישהו זוכר.

- מוצאים 3–5 שרשראות, רצוי ארוכות לאורך החוץ של התכנית, בשני הכיוונים.
- לכל קטע: אורכו בפיקסלים, מסימן לסימן, חלקי המספר שלו. שרשרת `150 / 210 / 95 / 340` ס"מ
  שנמדדת 69 / 97 / 44 / 157 פיקסלים נותנת כ־0.46 פיקסל לס"מ.
- מחשבים בנפרד את x (שרשראות אופקיות) ואת y (אנכיות). הם צריכים להסכים בטווח של אחוזים
  בודדים; אם לא, הצילום עקום או שמספר נקרא לא נכון – בודקים מה מהשניים.
- רק כשבשרטוט אין מידות בכלל, שואלים על מידה אחת ידועה.

## 2. קוראים עם רשת פיקסלים

</div>

```bash
npm run drawing:grid -- plan.jpg 150 120 520 420 --zoom 3
```

<div dir="rtl">

הכלי כותב חיתוך מוגדל של המלבן הזה (בפיקסלים של השרטוט) עם רשת כל 10 פיקסלים, מודגשת וממוספרת
כל 50, בקואורדינטות של השרטוט עצמו. עוברים על התכנית אזור אחרי אזור ורושמים קואורדינטות במקום
להעריך:

- **קירות**: שני הצדדים של כל קיר (קווים עבים או פסים מקווקווים). בקובץ התכנית החדרים יושבים על
  קווי האמצע של הקירות.
- **דלתות**: פתח בקיר עם קשת; מרכז הקשת הוא הציר, הרדיוס שלה הוא הכנף.
- **חלונות**: סימנים בקיר, לרוב עם תווית כמו `120 / 100 / UK=110` – רוחב, גובה, גובה אדן (ס"מ).
- **אביזרים**: ריצות מטבח, אסלה, מקלחת, אמבטיה, מיטות – איפה שהשרטוט מראה אותם.

**קו מידה הוא לא קיר.** הוא דק, יש לו סימנים בשני הקצוות ומספר עליו. מי שקורא אותו כפני קיר מזיז
שורה שלמה של חדרים בהפרש שלו.

## 3. בודקים כל חדר מול השטח שכתוב בו

ברוב השרטוטים כתוב בכל חדר השטח שלו (ולעיתים גם רוחב ועומק). מחשבים את השטח מהקריאה: חדר של
1.89 × 2.04 מ' הוא 3.86 מ"ר; חדר בצורת L הוא המלבן שלו ועוד הגומחה. אם המספר שלכם לא מסכים עם
השרטוט, קראתם קיר לא נכון – מוצאים אותו לפני שבונים. אם השרטוט סותר את עצמו (התווית אומרת דבר
אחד והקירות מראים אחר), בונים את מה שהשרטוט מראה ואומרים את זה.

## 4. מניחים את הקריאה על השרטוט לפני שבונים

כותבים את קובץ התכנית (חדרים על קווי האמצע של הקירות, פתחים במרכזם), ואז:

</div>

```bash
npm run drawing:overlay -- plan.jpg my-house --scale 46 --origin 172,153
```

<div dir="rtl">

`--scale` הוא פיקסלים למטר, `--origin` הוא הפיקסל בשרטוט שבו נמצא (0, 0) של התכנית. הכלי מצייר
על השרטוט את קווי המתאר של החדרים בכחול, דלתות בירוק, דלתות הזזה ופתחים בכתום וחלונות במג'נטה.
מסתכלים: כל קצה צריך לשבת על אמצע של קיר וכל פתח בתוך הפתח שלו. מתקנים ומריצים שוב עד שכן.
(`--storey 1` לקומה עליונה.)

## 5. אחרי הבנייה: המבט מלמעלה ליד השרטוט

פותחים את הבית, לוחצים M (מבט מלמעלה עם מידות), מצלמים מסך, ואז:

</div>

```bash
npm run drawing:overlay -- plan.jpg --compare top-view.png
```

<div dir="rtl">

השרטוט והבית זה לצד זה בתמונה אחת: שולחים אותה יחד עם הקישור. אחר כך מריצים את הבדיקה המלאה
(‏`__fullTest()` בדף, או `npm run check`).

## 6. אומרים מה לא ברור

סמל שלא זיהיתם, חדר שהשימוש בו לא כתוב, מידה שסותרת את האחרות: מפרטים אותם בדוח במקום למלא
בניחוש. פריטים שאין בספריית המודלים בגודל המשורטט – משטח של 1.2 מ', קיר קצר, גומחה – אפשר לבנות
כקופסת `details.panels` בדיוק בגודל הזה.
